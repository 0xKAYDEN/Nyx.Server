# Fix: Proper Packet Framing with Seal

## Problem
Packet framing was not including the 8-byte seal, causing:
```
Invalid packet length 20820 at offset 42 from KAYDEN
```

## Root Cause
The old `ConcurrentPacketQueue` was adding 8 bytes (`tqPadding`) to the packet length when dequeuing:

```csharp
// Old ConcurrentPacketQueue
currentPacketSize = ((length) + tqPadding); // tqPadding = 8
```

This is because the TQ packet format is:
- `[Length:2][Data:Length-4][Seal:8]`
- The Length field does NOT include the seal
- Total bytes = Length + 8

The new inline framing code was using `packetLen` directly, which didn't include the seal.

## Fix
Updated `ProcessEncryptedDataAsync` to include the 8-byte seal when extracting packets:

```csharp
const int SealSize = 8;
ushort packetLen = BitConverter.ToUInt16(buffer, offset);
int totalSize = packetLen + SealSize;  // Include seal

// Extract packet INCLUDING seal
byte[] packet = new byte[totalSize];
Buffer.BlockCopy(buffer, offset, packet, 0, totalSize);

offset += totalSize;
```

Also restored seal validation in `PacketHandler.HandlePacket`:
```csharp
// Validate client seal (TQClient) at offset Length
if (Length + 8 <= packet.Length)
{
    if (ClientSeal != BitConverter.ToUInt64(packet, Length))
    {
        client.Disconnect();
        return;
    }
}
```

- `src/Nyx/Program.cs` - Fixed packet framing to include seal
- `src/Nyx/Network/PacketHandler.cs` - Restored seal validation
