# Fixed: Missing Fields in LoadEntity and SaveEntity Methods

## Problem
After migrating from MySQL to PostgreSQL, the `LoadEntity` and `SaveEntity` methods in `EntityTable.cs` were significantly simplified and missing many important fields that were present in the original MySQL implementation.

## Root Cause
The PostgreSQL migration initially created minimal versions of `LoadEntity` and `SaveEntity` that only handled basic entity properties. Many game-critical fields were not being loaded or saved, including:
- Character appearance and stats (Face, HairStyle, etc.)
- Game state flags (SwordSoul, BansheeSpirit, DidBrightFortune, etc.)
- Inventory and storage related fields (WarehousePW, MoneySave, ExtraInventory, etc.)
- Guild and Union information
- Arena and PvP statistics
- Rebirth information
- Achievement data
- And many more...

## Solution
Restored the complete implementation from the MySQL version, adapted for PostgreSQL:

### Changes to `LoadEntity` method:
1. Added loading of all character appearance fields (Face, HairStyle)
2. Added loading of boolean flags (SwordSoul, BansheeSpirit, DidBrightFortune, etc.)
3. Added loading of merchant status and handling
4. Added loading of Union, Guild, and Clan information
5. Added loading of rebirth information (FirstRebornClass, SecondRebornClass, etc.)
6. Added loading of enlightenment and experience boost information
7. Added loading of nobility information
8. Added loading of Team Arena, Arena, and Champion Points statistics
9. Added loading of JiangHu information
10. Added loading of flowers
11. Added map validation for forbidden and PK-free maps
12. Added handling for newly created characters
13. Added loading of BlackList, DailySignDays, Wardrobe, and other special fields

### Changes to `SaveEntity` method:
1. Added saving of all character appearance fields
2. Added saving of boolean flags (converted to integers for database storage)
3. Added saving of merchant status
4. Added saving of Union, Guild, and Clan information
5. Added saving of rebirth information
6. Added saving of enlightenment and experience boost information
7. Added saving of DailySign, Wardrobe, and BlackList as formatted strings
8. Added saving of nobility-related fields
9. Added saving of Arena and PvP statistics
10. Added saving of special fields (ExtraInventory, CountryID, etc.)

### Additional Methods Added:
1. **SetFlowers**: Sets up the flowers system for the client based on character model
2. **TryReset**: Implements daily reset logic for various character stats

### Other Changes:
- Added `using System.Linq;` for Math.Min usage
- Fixed EntityRecord.Owner to be string type (username) instead of GameClient
- Ensured all field mappings between EntityRecord and Game.Entity are correct

## Files Modified
- `src/Nyx/Database/EntityTable.cs` - Complete rewrite of LoadEntity and SaveEntity methods, plus added missing helper methods
- `src/Nyx/Database/PostgreSQL/EntityRepository.cs` - Fixed Owner property type

## Verification
The updated methods now:
- Load and save all character data exactly as the MySQL version did
- Maintain compatibility with the PostgreSQL schema
- Properly handle all game systems (guilds, unions, arenas, etc.)
- Include all necessary validation and special handling

## Note
Some fields in EntityRecord have incorrect comments (marked as "DB: VirtuePoints" or "DB: Online"). These should be cleaned up in a future refactoring, but don't affect functionality.
