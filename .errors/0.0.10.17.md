# Fixed: NullReferenceException in Achievement.Load Method

## Problem
A `NullReferenceException` occurred at line 157 in `Achievement.Load` method when trying to load achievement data:

```
System.NullReferenceException
  HResult=0x80004003
  Message=Object reference not set to an instance of an object.
  Source=Nyx.Server
  StackTrace:
   at Nyx.Server.Game.Achievement.Load(String bas_line) in D:\Nyx\Nyx Last Stable\Nyx\src\Nyx\Network\GamePackets\[1136] - MsgAchievement.cs:line 157
```

## Root Cause
The `Achievement.Load` method had several issues:

1. **Insufficient null/empty check**: The method only checked if `bas_line.Length == 0`, but didn't handle `null` strings
2. **No array bounds checking**: The method assumed the split string would always have at least 13 elements, causing `IndexOutOfRangeException` when loading entities with empty or incomplete achievement data
3. **No error handling for parsing**: The method used `uint.Parse` without try-catch, which would throw exceptions on invalid data
4. **Missing initialization for new entities**: When creating new entities, the Achievement field in EntityRecord was not initialized, resulting in null values being passed to the Load method

## Solution
Made the following fixes:

### 1. Fixed Achievement.Load method (MsgAchievement.cs, line 157)
```csharp
// Before:
public void Load(string bas_line)
{
    if (bas_line.Length == 0) return;
    string[] line = bas_line.Split('#');
    for (byte x = 0; x < 13; x++)
        BitVector32.bits[x] = uint.Parse(line[x]);
}

// After:
public void Load(string bas_line)
{
    if (string.IsNullOrEmpty(bas_line)) return;
    string[] line = bas_line.Split('#');
    for (byte x = 0; x < 13 && x < line.Length; x++)
    {
        if (uint.TryParse(line[x], out uint value))
            BitVector32.bits[x] = value;
        else
            BitVector32.bits[x] = 0;
    }
}
```

**Changes:**
- Changed `bas_line.Length == 0` to `string.IsNullOrEmpty(bas_line)` to handle null strings
- Added array bounds check: `x < line.Length`
- Changed `uint.Parse` to `uint.TryParse` with fallback to 0 on parse failure

### 2. Initialized Achievement field for new entities (EntityTable.cs)
In the `CreateEntity` method, added initialization of the Achievement field:
```csharp
// Added:
Achievement = ""
```

This ensures that new entities have an empty achievement string instead of null, preventing NullReferenceException when loading.

## Files Modified
- `src/Nyx/Network/GamePackets/[1136] - MsgAchievement.cs` - Fixed Load method with proper null checking and error handling
- `src/Nyx/Database/EntityTable.cs` - Added Achievement field initialization for new entities

## Verification
After these fixes:
- New characters can be created without NullReferenceException
- Existing characters with empty or incomplete achievement data can be loaded safely
- Characters with valid achievement data continue to load correctly
- Invalid achievement data is handled gracefully (set to 0)

## Note
The PostgreSQL implementation stores achievement data in the `entities` table (in the `Achievement` column) rather than in a separate `achievement` table. This is different from the MySQL version but works correctly with the current database schema. The static `Achievement.Load(GameClient)` method that references the separate achievement table is not used in the PostgreSQL version.
