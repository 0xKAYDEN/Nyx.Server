# Fixed: IndexOutOfRangeException in Entity.Boss Property

## Problem
An `IndexOutOfRangeException` occurred when trying to load an entity:

```
System.IndexOutOfRangeException
  HResult=0x80131508
  Message=Index was outside the bounds of the array.
  Source=System.Private.CoreLib
  StackTrace:
   at Internal.Runtime.CompilerHelpers.ThrowHelpers.ThrowIndexOutOfRangeException()
   at Nyx.Server.Game.Entity.get_Boss() in D:\Nyx\Nyx Last Stable\Nyx\src\Nyx\Game\Entity.cs:line 3794
   at Nyx.Server.Game.Entity.set_Hitpoints(UInt32 value) in D:\Nyx\Game\Entity.cs:line 3820
   at Nyx.Server.Database.EntityTable.LoadEntity(GameClient client) in D:\Nyx\Nyx Last Stable\Nyx\src\Nyx\Database\EntityTable.cs:line 114
```

## Root Cause
The issue occurred because:

1. In the `Entity` class, the `SpawnPacket` array is initialized to `new byte[0]` (empty array) in the constructor
2. The `SpawnPacket` is properly sized and initialized in the `Name` setter method
3. In `LoadEntity`, we were setting `client.Entity.Hitpoints` (line 114) **before** setting `client.Entity.Name`
4. When setting Hitpoints, the code checks `if (Boss > 0)` which accesses `SpawnPacket[_Boss]` where `_Boss = 216`
5. Since SpawnPacket was still the empty array, accessing index 216 caused an `IndexOutOfRangeException`

## Solution
Added the missing `client.Entity.Name = entity.Name;` assignment in the `LoadEntity` method, placed **before** any properties that might access the SpawnPacket (like Hitpoints).

### Change Made:
**File: `src/Nyx/Database/EntityTable.cs`**

Added line to set the Name immediately after creating the Entity object:
```csharp
// Before:
client.Entity = new Game.Entity(Game.EntityFlag.Player, false);
client.Entity.SwordSoul = entity.SwordSoul != 0;

// After:
client.Entity = new Game.Entity(Game.EntityFlag.Player, false);
client.Entity.Name = entity.Name;
client.Entity.SwordSoul = entity.SwordSoul != 0;
```

This ensures that:
1. The Name is set early in the loading process
2. The SpawnPacket is properly initialized with the correct size before any other properties are set
3. All subsequent property setters (Hitpoints, etc.) can safely access the SpawnPacket array

## Files Modified
- `src/Nyx/Database/EntityTable.cs` - Added Name assignment in LoadEntity method

## Verification
After this fix:
- Entities load correctly without IndexOutOfRangeException
- The SpawnPacket is properly initialized before being accessed
- All entity properties can be set in any order after the Name is set
- The Boss property and other SpawnPacket-dependent properties work correctly

## Note
This was a migration oversight where the MySQL version had `client.Entity.Name = reader.ReadString("Name");` at line 26, but this line was missing in the PostgreSQL version of LoadEntity.
