# Fix: Wrong Seal Value in PacketBuffer.WriteSeal

## Problem
Client would disconnect immediately after auth server forwarded it to the game server. The DH key exchange handshake was never completing.

## Root Cause
The `PacketBuffer.WriteSeal()` method was writing `"TQClient"` (0x746E65696C435154) as the packet seal, but the server should write `"TQServer"` (0x7265767265535154).

### Backup (working):
```csharp
// GameClient.Send() uses SafeWriter.Write with Constants.ServerKey = "TQServer"
Network.SafeWriter.Write(Constants.ServerKey, buffer.Length - 8, _buffer);
```

### Current (broken):
```csharp
// GameClient.Send() uses PacketBuffer.WriteSeal which writes "TQClient"
Network.PacketBuffer.WriteSeal(pooledBuffer, buffer.Length - 8);
```

The client expects server packets to end with `"TQServer"`. When it receives `"TQClient"` instead, it rejects the packet and disconnects.

## Fix
Updated `PacketBuffer.WriteSeal()` to write `"TQServer"` instead of `"TQClient"`:

```csharp
public static void WriteSeal(Span<byte> buffer, int offset)
{
    // "TQServer" as little-endian uint64
    // T=0x54, Q=0x51, S=0x53, e=0x65, r=0x72, v=0x76, e=0x65, r=0x72
    WriteUInt64(buffer, offset, 0x7265767265535154);
}
```
